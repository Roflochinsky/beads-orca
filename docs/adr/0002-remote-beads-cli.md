# Удалённое выполнение сохраняет семантику Beads CLI

Владелец принял Q22: для SSH-проектов предпочтителен структурированный вызов штатного `bd` через явно настроенный системный SSH. Плагин не извлекает секреты Orca, не подменяет удалённый проект локальным каталогом и не меняет backend Beads ради интеграции.

## Рассмотренные альтернативы

- Терминальный ввод Orca с чтением экрана не даёт контракт stdout/stderr/exit code и потому не подходит как транспорт данных.
- `bd serve` с port forward требует отдельного процесса и endpoint; в проверенной версии 1.3.2 он не поддерживает embedded Dolt и не воспроизводит CLI hooks и per-command auto-commit.
- Только авторизация Orca без дополнительной настройки: универсальный структурированный exec/file API в проверенной plugin-поверхности не подтверждён.

## Последствия

Remote остаётся обязательным сценарием roadmap. Для paired runtime без SSH требуется отдельный подтверждённый адаптер; неподдерживаемые или недоступные подключения должны быть видны, а не исчезать как пустые проекты. Установка helper, запуск сервера и открытие портов не выполняются автоматически. Это решение о будущей реализации, не подтверждение готового remote transport.

Первичные источники и ограничения: [integration-constraints.md](../integration-constraints.md).
